# LifeTime 팀 연결 규칙

이 문서는 팀이 합의한 프론트엔드·백엔드 연결 기준이다. 이후 기능 개발과 데이터 처리에서도 적용하며, 계약 변경이 필요하면 먼저 사용자와 합의한다.

| 항목 | 결정 |
| --- | --- |
| 시설 종류 | `aed`, `emergency_room` |
| 좌표 필드 | `latitude`, `longitude` |
| 거리·시간 단위 | `distance_m`는 미터, `duration_sec`는 초 |
| 날짜·시간 | 시간대가 포함된 ISO 8601, 판단 기준 `Asia/Seoul` |
| 누락 정보 | `null` 사용, `0`·휴무로 대체하지 않음 |
| 시설 수정 | 일반 사용자 불가 |
| 현재 위치 | 기본적으로 DB에 저장하지 않음 |
| 개발 연결 | 팀원은 가짜 데이터로 시작하고 API 완성 시 교체 |

| API | 기능 |
| --- | --- |
| `GET /api/facilities/nearby` | 위치·시설 종류로 주변 조회 |
| `GET /api/facilities/{id}` | 시설 상세 |
| `POST /api/aeds/recommendations` | 출발 위치·시각에 따른 AED 경로 비교 |

## 적용 기준

- 운영시간 정보가 없으면 휴무나 이용 불가로 단정하지 않는다. 요일별 운영시간은 한국 현지 시각으로 해석하고, 날짜가 있는 시각은 시간대가 포함된 ISO 8601로 교환한다.
- 도보 거리·소요시간은 실제 경로 공급자의 결과를 사용한다. 주변 검색의 지리적 거리를 도보 경로 거리나 도보 시간으로 오인하도록 반환하지 않는다.
- 개발용 가짜 데이터는 실제 데이터와 구분하고 운영 DB에 적재하지 않는다. API 완성 후 데이터 공급처를 교체할 수 있도록 동일한 연결 규칙을 따른다.
- 기존 주변 조회 응답의 최상위 구조는 `{"facilities": [], "count": 0}`이다. 전체 응답 필드가 아직 합의되지 않은 기능은 별도 합의 없이 완성된 계약으로 간주하지 않는다.

## 추천 성공 응답 (2026-10-21 사용자 승인)

```json
{
  "recommendations": [
    {
      "facility_id": "00000000-0000-0000-0000-000000000001",
      "distance_m": 120,
      "duration_sec": 100,
      "arrival_at": "2026-10-21T12:01:40+09:00",
      "availability": "unknown"
    }
  ],
  "count": 1
}
```

`availability`는 `available`, `unavailable`, `unknown` 중 하나다. unknown은 운영시간·휴무 정보 부족을 뜻한다. 위 예시는 계약 설명용이며 실제 시설·경로 결과가 아니다. 출발 입력은 기존 `start`, `departure_at`을 유지한다. 후보는 기본 주변 반경 3000m 이내 가까운 10개까지 경로를 조회하고 duration_sec, distance_m 순으로 비교한다.

현재 시설 스키마에는 공휴일·임시휴무 정보가 없다. 신뢰할 수 있는 휴무 달력이 연결되지 않은 경우 정규 운영시간 안이라도 available로 추정하지 않고 unknown을 반환한다. 외부 경로 인증키가 없으면 기존 503을 유지하며 Mock은 테스트에서만 주입한다.
